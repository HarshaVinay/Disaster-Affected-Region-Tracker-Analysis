# Disaster Affected Region Tracker Analysis – P1

## Project scope
This project implements the supplied P1 requirements:
- Clean dirty CSV disaster data using Python/Pandas.
- Apply the specified business rules.
- Load clean tables into MySQL.
- Run SQL analytics.
- Create five Matplotlib/Seaborn dashboard charts.

## Supplied business rules
1. Missing disaster types -> `Unknown`
2. Invalid dates -> safely converted to null (`NaT` in Pandas; `NULL` in MySQL)
3. Missing population -> median population
4. Missing affected people -> `0`
5. Missing economic losses -> `0`
6. Aggregate total affected people per region

## 1. Create a virtual environment



Make sure MySQL Server is installed and running.

Copy:
```text

```

Then edit `.env` with your MySQL username/password.

Run:


The script creates the `disaster_tracker` database, creates the clean tables, and loads the cleaned data.

You can then run the queries in:
```text

```

## Important data-model note

The supplied `regions.csv` contains many `region_id` records but only eight region names. Therefore, the disaster fact analysis uses the `region` field from `disaster_events_clean` and does not join the disaster events to `regions_clean` by region name. Joining on that field would duplicate disaster rows because multiple region records share the same region name.

The project therefore preserves the supplied region table while keeping disaster/impact analytics at the event-region level.

## Scope limitation

The supplied CSVs contain region names, dates, severity, affected population, and economic loss, but they do not contain latitude/longitude, satellite imagery, GIS geometries, or remote-sensing bands. Therefore, this local implementation produces region-level analytical dashboards rather than true geographic maps. Actual GIS/satellite mapping would require additional spatial data.
